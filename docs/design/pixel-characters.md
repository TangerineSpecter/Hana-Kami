# 办公室像素角色微调准则

记录日期：2026-09-20。适用于菲伦、银月、胡桃、阿尼亚、可莉等办公室全身角色的绘制与修改。

**以菲伦为比例和观感基准：脸部紧凑、脸颊自然收拢、下巴圆润、表情轻柔。优先保留原有角色造型，每次只改用户指出的部位。**

这份记录整理本轮反馈形成的方向，不表示每个角色的最后一版都已获得用户最终认可。后续明确反馈优先于本记录。

## 1. 「按照菲伦处理」具体指什么

基准是 [feilenArt.ts](../../src/renderer/src/scene/office/feilenArt.ts) 与 [菲伦预览](../../outputs/feilen-preview.html)。先看实际渲染，不凭代码坐标判断是否相似。

| 参考项 | 要达到的效果 |
| --- | --- |
| 头身比例 | 头部、身体、四肢协调，避免大头叠小身子；戴帽子或有兽耳不等于脸也要放大。 |
| 脸部留白 | 眼睛、脸颊、嘴巴和下巴之间紧凑但能分清，不留一大片横向肤色。 |
| 下颌轮廓 | 脸颊逐步收向下巴，圆润而有收束；既不要宽平下巴，也不要削成尖锐倒三角。 |
| 像素表现 | 清晰整数像素，细节密度协调；放大时不糊，办公室实际尺寸下也能辨认。 |
| 四向造型 | 正面、背面、侧面的头部体积与身体比例一致，侧脸独立绘制。 |

菲伦是观察和比较的基准，不是要求所有角色换成同一张脸、同一套发型或同一种原始分辨率。发饰、帽子、耳朵、发型、衣服及背包仍应保留角色辨识度。

## 2. 脸宽：收紧观感，不要一口气缩成小脸

用户反复指出的「大饼脸」「比菲伦高而且宽」，不一定只是脸部多边形太宽，也可能来自鬓发覆盖少、额头露得多、腮红铺得宽，或下巴与脖子、领口颜色连成一片。

处理顺序：

1. 与菲伦按同一显示高度、脚底基线和朝向比较，分别看头发外轮廓和实际露出的肤色范围。
2. 先微调脸颊边界、鬓发覆盖和腮红范围。需要时配合调整眼距，避免眼睛挤到轮廓上。
3. 再检查下巴到脖子、衣领的衔接，不要靠缩放整个角色解决脸宽。
4. 每轮改一小档并预览。32×48 的角色一像素就很明显，不把「左右各缩一像素」当成固定配方。

胡桃本轮曾先收窄两侧，用户反馈「小了点」，随后回放一像素。这说明目标是适度收拢，而不是越窄越好。不同原始尺寸也不能照搬同一像素改变量。

## 3. 下巴与轮廓：避免胡子、双嘴和方框

- 胡桃曾用头发的深棕色画脸部外沿，连成一圈后像胡子。脸颊和下颌优先用接近肤色的柔和阴影，深色头发边界留在发丝处。
- 阿尼亚脖子曾出现「外圈深肤色、里面一块浅色」的方框，看着像第二张嘴。脖子用简洁的形状，不画封闭的小色框。
- 嘴巴、下巴、领口必须读得清楚。不要让下巴阴影与嘴连成粗线，也不要让浅色脖子和衣领把脸向下拉长。
- 侧脸保持整体圆润，眼睛下方保留肤色过渡。不要把正脸五官整体翻转来充当侧脸，也不要擅自给原本无嘴的侧脸加嘴。

## 4. 嘴巴：小、浅、自然，符合角色气质

默认从轻柔的闭嘴微笑开始，保留角色已有且用户未要求改变的表情。开口笑只在用户提出时尝试；用户要求恢复微笑后，不再自行加回开口或嘴内细节。

| 本轮问题 | 后续处理原则 |
| --- | --- |
| 阿尼亚的开口笑不对味 | 单纯加宽或加深开口不等于可爱，不用不断加大嘴巴来补表情。用户最终要求闭嘴微笑。 |
| 可莉曾被反馈单边挑嘴角显得「嚣张」，随后用户又要求恢复轻轻上扬的那版 | 保留轻柔的小幅度，不把中途反馈固化成「一律不能单边上扬」；以用户最新指定的版本为准。 |
| 对称 U 形笑嘴生硬 | 降低弯曲的视觉强度，缩小嘴形、减淡嘴角，检查实际显示尺寸。 |
| 修改脸型时顺手改掉微笑 | 脸型与表情分开处理；不能因为借鉴菲伦，就删掉角色原有的笑嘴。 |

不要把某组嘴巴坐标推广到所有角色。原始分辨率、眼睛位置、肤色和下巴余量都影响效果。嘴型修改默认只涉及嘴部像素。

## 5. 四向与动作：避免背面出现多余的手

胡桃的背面工作帧曾同时保留下垂的手，又叠加抬起的手，形成重复手部。手臂离身体过远、袖口横向突起，也会像小翅膀。

- 待机、走路：袖子连接肩部，小手从袖口露出；左右摆动自然，不悬空。
- 打字、阅读：手臂朝身体前方，背面应受躯干、头发或背包遮挡，不能为了显示动作把手和书画到身体外侧。
- 每个动作只保留一对手。检查正背侧、四个动作及其动画帧，而不只检查正面待机。
- 家具由场景绘制。坐姿预览需检查桌沿遮挡和手的位置，预览示意不等于办公室实景已经验证。

## 6. 角色差异与本轮回退记录

| 角色 | 当前绘制尺寸 | 后续需要保留的方向 |
| --- | --- | --- |
| 菲伦 | 32×48 | 比例参考，不因修改其他角色而顺带改她。 |
| 银月 | 32×48 | 银白长发、兽耳、蓝灰眼与红腰结；保留已有表情。耳朵曾单独调整，不能因改脸而又改回旧耳朵。 |
| 胡桃 | 32×48 | 现有帽冠高度、花饰、红眼和小微笑；脸宽适中，下巴不用深发色围边；背面手部注意遮挡。 |
| 阿尼亚 | 32×48 | 粉色短发、绿眼、黑金发饰、蓝色背带裙；紧凑脸型和闭嘴微笑，避免方框脖子。 |
| 可莉 | **64×96** | **保留原版整体造型，只微调脸型和嘴巴。**红帽、羽毛、双马尾、精灵耳、衣服、背包、嘟嘟可和原有动作保持原样。 |

可莉曾整体重画为 32×48，用户明确否定并要求还原。该方案已撤回，不能当成以后重做可莉的基准，也不能因为「参考菲伦」再次强制转换她的分辨率。可莉嘴型在对称淡笑之后，用户又明确要求恢复「嘴角轻轻上扬」的版本：短横弧加一侧轻抬的嘴角、颜色 `#b77878`。当前以这版为准，不擅自改回对称笑嘴。

## 7. 下次修改的执行方式

1. **先确认当前版本。**查看 Git 差异、当前预览和用户是否已回退；保留用户已有更改，不把被否定的实验重新套回去。
2. **明确本轮部位。**用户说改嘴就只改嘴；说脸宽就优先改脸部露出范围。已有辨识度不错的角色默认局部修改，不自动扩展成整体重画。
3. **保留对照。**保存修改前的参考图或可恢复版本，与修改后同倍率查看；每轮只改变一个问题，避免同时改帽子、头发、脸和衣服。
4. **同时看放大与实用尺寸。**放大检查像素边界，办公室尺寸检查表情是否读得出来。不要只凭放大图宣称效果成立。
5. **刷新实际预览。**修改代码后重新生成页面，打开相应方向和动作供用户判断。已有本地服务可继续使用，不随意重启角色或智能体。
6. **区分验证与认可。**渲染、类型检查通过表示代码可用，不表示用户已认可造型。未认可的方案不要写成定稿。

已明确授权的局部修改直接完成并展示，不额外引入逐步审批。如果用户明确说「先分析、不修改」，则先分析。

## 8. 文件入口与验证

角色绘制位于 [scene/office](../../src/renderer/src/scene/office)，如 `feilenArt.ts`、`yinyueArt.ts`、`hutaoArt.ts`、`anyaArt.ts` / `anyaHeadArt.ts`、`kleeArt.ts`。办公室全身动画与卡片静态头像是两套资源；修改全身角色不应顺便重做卡片头像。

预览命令示例：

```sh
node tools/render-klee.mjs
node tools/preview-klee.mjs
```

银月、胡桃、阿尼亚有对应的 `render-*.mjs` 和 `preview-*.mjs`；菲伦参考页使用 `node tools/preview-feilen.mjs`。页面输出在 `outputs/*-preview.html`，通过当前可用的本地 HTTP 服务查看，端口以实际运行状态为准。

涉及绘制逻辑或尺寸变化时运行 `npm run typecheck:web`，并运行对应帧渲染检查；提交前检查 `git diff --check`。低风险的像素坐标或颜色微调以实际渲染检查为主，不为几个像素另写一套重复实现的测试。

可直接复用的任务说明：

> 请参考菲伦的头身比例、脸部留白和四向观感，在当前角色原版上做局部微调。脸颊适度收拢、下巴圆润，避免宽平脸和深色胡子状轮廓；表情轻柔自然。保留帽子、发型、衣服和已有辨识度。不要强制统一分辨率，尤其可莉继续保留原版 64×96。每轮只处理我指出的部位，并展示真实预览。
